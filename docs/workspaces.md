# 개인 연습 공간과 공식 매장

회원가입 후 내 자료로 연습하기, 초대 코드로 매장 참여, 매장 만들기를 선택합니다. 각자 자신의 이메일로 가입하며 매장 참여는 관리자의 승인이 필요합니다.

## 시작과 전환

- 개인 공간은 계정당 하나이며 `기본` 카테고리 하나와 빈 상품 목록으로 시작합니다. 메뉴·사진·유사 상품 그룹을 직접 준비합니다.
- 새 공식 매장도 빈 POS로 시작합니다. 가입자는 매장을 만들거나 한 공식 매장에 참여할 수 있으며, 개인 공간을 함께 유지할 수 있습니다.
- 상단 사용 공간 선택기와 내 계정에서 공간을 전환합니다. 기존 입력·연습을 저장 또는 종료했는지 확인하는 안내를 제공합니다. 화면을 바꾸면 해당 화면의 진행 상태가 초기화되므로 저장할 내용을 먼저 확인해야 합니다.
- 로그인은 계정의 마지막 선택 공간을 복원하며, 로그인된 세션끼리는 서로 다른 공간을 사용할 수 있습니다. 권한이 없어진 공간은 선택 화면에서 다시 선택해야 합니다.
- 공식 매장 승인 대기 중에도 개인 공간을 생성하고 이용할 수 있습니다. 승인 시 이미 선택한 개인 공간은 유지합니다.

## 권한과 기록

| 동작 | 개인 공간 소유자 | 공식 매장 근무자 | 공식 매장 관리자 |
| --- | --- | --- | --- |
| 공간 상품 학습·내 기록 | 가능 | 가능 | 가능 |
| 메뉴·사진·분류·퀴즈 그룹 수정 | 가능 | 제한 | 가능 |
| 업무 평가 응시 | 제한 | 가능 | 제한 |
| 공식 매장 근무자 집계·결과 조회 | 제한 | 제한 | 가능 |

사진과 기록은 현재 공간과 소유자를 함께 검사합니다. 개인 학습은 해당 사용자의 개인 공간에 저장하고 공식 매장 관리자 통계에 포함하지 않습니다. 상품이 적으면 카테고리 등 연습은 상품을 다시 출제해 5문항을 완료할 수 있습니다. 사진·유사 그룹이 부족한 단계는 준비할 자료를 안내합니다.

## API

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/auth/session` | 계정·현재 공간·접근 가능한 공간 목록·현재 공식 매장 역할 |
| `GET /api/v1/workspaces` | 접근 가능한 공간 목록과 현재 선택 조회 |
| `POST /api/v1/workspaces/personal` | 개인 공간 생성 또는 기존 개인 공간 선택. 반복 요청은 같은 공간 반환 |
| `POST /api/v1/workspaces/select` | `workspace_id`로 접근 가능한 공간 선택 |
| `GET /api/v1/workspaces/readiness` | 사진 수와 출제 가능한 유사 그룹 준비 여부 |

자료·학습 API의 `X-Bread-Workspace` 헤더가 현재 세션 공간과 다르면 409를 반환합니다. 화면은 공간을 바꿀 때 상품·사진·문항·재고 컴포넌트를 새로 생성하고 이전 조회를 취소합니다. 재고 세션의 브라우저 보관 키도 사용자·공간을 함께 사용합니다.

## 데이터 이전

- `workspace_metadata`는 공간 종류와 개인 소유자를 저장합니다. 기존 매장 ID와 공식 소속 테이블을 유지합니다.
- `workspace_selections`는 로그인 세션별 현재 공간을, `workspace_preferences`는 재로그인할 때 복원할 공간을 저장합니다.
- 기존 매장의 기본 상품과 수정 내용을 시작 시 한 번 `store_categories`, `store_menus`, `workspace_product_metadata`에 보존합니다. 이후에는 저장된 공간 자료를 조회합니다.
- 이전은 한 트랜잭션으로 진행하며 실패하면 데이터 변경이 롤백됩니다. 재시작으로 이전을 중복 실행하지 않습니다. 운영에서는 DB 백업 후 재시작하고 복사본에서 검증합니다.

개인 자료의 공식 매장 복사, 여러 공식 매장 동시 소속, 퇴사·탈퇴 처리는 후속입니다. 공개 무료 데모의 계정 API는 계속 비활성 상태이며 영속 저장·백업을 검증한 환경에서 실제 계정 운영을 시작합니다.

## 검증

백엔드에서 빈 공간·권한·사진·기록 격리·초대 승인·세션별 선택·로그인 복원·마이그레이션 반복 및 실패 롤백을 확인합니다. 브라우저는 임시 DB를 사용하는 API에 연결해 회원가입·개인 메뉴 저장·공식 매장 생성·공간 전환·새로고침 및 모바일 배치를 검증합니다. 실제 로컬 DB의 복사본에서는 기존 상품·분류·계정·학습 기록 수와 외래키를 대조합니다.
