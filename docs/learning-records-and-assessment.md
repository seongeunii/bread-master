# 학습 기록 · 오답 노트 · 업무 평가

이 문서는 구현된 연습 기록과 업무 평가의 저장·채점·조회 흐름을 설명합니다. 평가 결과는 매장 관리자가 확인하는 교육 기록이며, 급여·근태·인사 시스템과 연결되지 않습니다.

## 사용자 흐름

### 연습과 학습 기록

1. 로그인한 매장 구성원이 퀴즈, 배달 또는 POS 연습을 시작합니다.
2. 승인된 매장 계정으로 시작한 세션은 사용자·매장·연습 모드와 함께 기록됩니다. 비회원 공개 체험은 개인 학습 이력에 연결되지 않습니다.
3. 서버가 채점한 연습을 완료하면 결과와 완료 시각을 저장합니다. 도감 탐색이나 채점하지 않은 진행 상태는 학습 통계에 더하지 않습니다.
4. 근무자는 **내 계정 → 내 학습 현황**에서 모드별 풀이 수·정답률과 풀이 기록을 보고, 저장 가능한 오답은 당시 문항의 보기로 다시 풀 수 있습니다.

오답 재풀이는 원래 기록을 수정하지 않고 새 연습으로 저장합니다. 현재 보기 스냅샷이 있는 선택형 퀴즈 오답만 재도전할 수 있습니다. 배달·POS 주문 기록은 상품별 기대 수량과 입력 수량 차이를 보여주며 문항 재도전 기능은 제공하지 않습니다. 재고 등록은 채점하지 않으므로 오답 노트와 정답률에서 제외합니다.

관리자는 **근무자 학습 현황**에서 같은 매장 근무자의 풀이 수, 채점된 풀이 수, 정답률, 최근 학습일을 확인합니다. 여기에 표시되는 레벨 1~3은 누적 정답 수로 계산하는 임시 구간이며 랭킹·보상 등급이 아닙니다.

### 업무 평가

평가는 일반 연습과 분리된 응시 기록입니다. 승인된 근무자만 시작할 수 있으며, 문항과 선택 답안은 `assessments`와 `assessment_questions`에 별도로 저장합니다.

| 영역 | 문항 수 | 출제 형태 |
| --- | ---: | --- |
| 카테고리 분류 | 2 | 상품 사진을 보고 POS 카테고리 선택 |
| 사진 보고 상품명 선택 | 2 | 사진을 보고 보기에서 상품명 선택 |
| 이름 보고 사진 선택 | 2 | 상품명을 보고 보기에서 사진 선택 |
| 배달 상품 찾기 | 2 | 주문 상품명을 보고 맞는 상품 선택 |
| POS 메뉴 찾기 | 2 | 상품을 보고 POS 메뉴 선택 |
| **합계** | **10** | **100점 만점** |

각 문항은 같은 배점이며 총점은 정답 수에 따라 100점 만점으로 계산합니다. 답안을 선택할 때 서버에 저장하므로 새로고침 후에도 이어 풀 수 있고, 제출 전에는 답을 바꿀 수 있습니다. 모든 문항에 답해야 제출할 수 있습니다. 제출 전에는 정답 여부를 공개하지 않습니다. 제출 뒤 근무자는 총점과 영역별 정답 수를 볼 수 있습니다.

평가 시작 시 사진이 있는 상품 4개 이상과 2개 이상의 카테고리가 필요합니다. 사진 보고 상품명·이름 보고 사진 영역에는 출제 가능한 활성 유사 상품 그룹과 충분한 사진 상품이 필요합니다. 조건이 부족하면 서버가 응시 시작을 거절하고 필요한 데이터를 안내합니다. 이미 진행 중인 응시가 있으면 새 응시 대신 이를 반환합니다. 제출 뒤 다시 시작하면 새 응시가 생성됩니다. 시간 제한과 응시 횟수 제한은 없습니다.

평가 정책 버전은 응시 생성 시 저장합니다. 현재는 `mixed-v2-10`이며, 이전 5문항 버전의 완료 결과도 삭제하거나 새 정책으로 다시 계산하지 않습니다. 관리자는 **근무자 학습 현황 → 평가 결과 보기**에서 같은 매장 승인 근무자의 제출 결과 중 총점·영역별 정답 수·제출 시각만 확인합니다. 개별 답안과 평가 중 선택 사항은 관리자 결과 요약에 포함되지 않습니다.

## API와 권한

| 메서드·경로 | 권한 | 역할 |
| --- | --- | --- |
| `GET /api/v1/store-admin/my-learning` | 로그인한 매장 구성원 | 본인의 풀이 기록·오답 노트·모드별 통계 조회 |
| `POST /api/v1/store-admin/my-learning/{exercise_id}/retry` | 로그인한 매장 구성원 | 본인 오답의 저장된 문항으로 새 연습 시작 |
| `GET /api/v1/assessments/mine` | 승인된 근무자 | 본인의 진행 중 평가와 제출 결과 조회 |
| `POST /api/v1/assessments/start` | 승인된 근무자 | 진행 중 평가 이어받기 또는 새 10문항 응시 생성 |
| `POST /api/v1/assessments/{assessment_id}/questions/{question_id}/answer` | 응시 소유 근무자 | 보기 검증 후 답안 저장·변경 |
| `POST /api/v1/assessments/{assessment_id}/submit` | 응시 소유 근무자 | 미응답 확인, 서버 채점, 최초 결과 확정 |
| `GET /api/v1/assessments/store-results?worker_id=…` | 매장 관리자 | 같은 매장 승인 근무자의 제출 결과 요약 조회 |

각 평가 조회·수정은 응시자의 사용자 ID와 매장 ID를 함께 확인합니다. 관리자 조회는 대상 근무자가 해당 관리자의 매장에 승인 상태로 소속되어 있는지 검증합니다. 다른 매장 데이터는 조회할 수 없습니다.

## 저장 구조

- `store_exercises`: 매장 구성원이 완료한 연습의 소유자·매장·모드·결과·완료 시각과 문항 스냅샷을 저장합니다.
- `assessments`: 사용자·매장·정책 버전·제출 시각·확정 결과를 보관합니다.
- `assessment_questions`: 평가 순서, 당시 문항과 보기, 서버 정답 키, 근무자 답안을 보관합니다.
- 평가 제출은 누락 답안을 먼저 검사한 뒤 서버에서 결과를 계산합니다. 이미 제출된 평가를 다시 제출하면 최초 확정 결과를 반환합니다.

관련 구현은 `backend/app/store_learning.py`, `backend/app/store_admin.py`, `backend/app/assessments.py`, `frontend/src/features/learning/Assessment.tsx`에 있습니다. 전체 관계는 [ERD](erd.md), 제품 우선순위와 구현 상태는 [제품 계획](development.md)을 참고하세요.

## 미구현·운영 제한

- 레벨은 임시 학습 지표입니다. 매장 내 경쟁 랭킹, 보상 포인트, 급여 조정이나 인사 결정과 연동되지 않습니다.
- 기록 보존 기간, 탈퇴·퇴사·매장 이동 시 삭제 및 이전 정책은 확정되지 않았습니다.
- 평가 시간·재응시 간격·횟수 제한과 이의 제기 절차는 미구현입니다.
- 평가의 POS 영역은 4개 보기에서 메뉴를 찾는 문항입니다. 실제 POS 화면에서 장바구니를 구성하고 결제하는 동작을 평가하지 않습니다.
- Render 무료 공개 데모는 계정 API를 비활성화하므로 개인별 기록과 업무 평가를 사용할 수 없습니다. 계정 운영은 영속 저장소·백업·복구 조건을 검증한 뒤 별도로 활성화해야 합니다.
